内存优化 — FerriteCore / MemoryFix 理念
减少堆内存占用，降低 GC 压力，提升整体吞吐量
方块状态缓存
Memory
缓存常用方块状态的属性查询结果，避免重复计算光照、碰撞等数据。LRU 缓存上限可配置。
BlockBehaviour.BlockStateBase cache size: 65536
实体数据压缩
Memory
将实体坐标、旋转、生命值等打包到紧凑的 long 字段中，单个实体节省约 40 字节堆内存。
CompactEntityData 3 longs / entity
NBT 标签去重
Memory
使用 ConcurrentHashMap 对相同内容的 NBT 标签进行去重，减少堆中重复对象的数量。
CompoundTag thread-safe
BlockPos 对象池
Memory
使用 ThreadLocal 复用 BlockPos 实例，减少高频方块位置操作产生的 GC 压力。
PooledBlockPos per-thread
区块调色板优化
Memory
自动压缩区块段中的调色板数据，对空段落使用单值调色板，减少每段内存占用。
LevelChunkSection PalettedContainer.compact()
弱引用区块缓存
Memory
使用 WeakReference 缓存区块文件对象，在内存压力下允许 GC 自动回收，避免 OOM。
RegionFileStorage auto-evict
实体优化 — Lithium 理念
减少实体 AI 计算开销，跳过不必要的物理与寻路
远距离实体 AI 跳过
CPU
距离玩家超过 32 格的实体跳过完整 AI tick，大幅减少远端实体的 CPU 开销。
entityAiSkipDistance: 32
非活跃 AI 降频
CPU
非活跃实体（不在 EAR 范围内）的 AI tick 频率降低到每 4 tick 一次，减少 75% 的 AI 开销。
interval: 4 ticks
冗余寻路跳过
CPU
检测实体位置未发生变化时跳过寻路重计算，避免重复路径搜索消耗 CPU。
position threshold
生物目标搜索优化
CPU
根据生物类型动态缩减目标搜索范围，并降低搜索频率，减少每 tick 的实体扫描开销。
dynamic range
村民传感器降频
CPU
将村民 POI 传感器更新间隔从每 tick 降低到每 20 tick，大幅减少村庄计算开销。
interval: 20 ticks
掉落物物理跳过
CPU
地面上的静止掉落物跳过物理计算，仅保留拾取检测，减少大量物品实体的开销。
velocity < 1e-6
客户端优化 — 服务端驱动
通过服务端调整数据包与实体行为，直接降低客户端渲染负载
核心思路：Sodium / ImmediatelyFast 是纯客户端渲染优化模组，无法直接移植到服务端。但服务端可以通过减少发送给客户端的实体数量和数据包频率来达到等效甚至更好的客户端 FPS 提升效果。Mirage 通过调整实体追踪范围、刷怪上限、更新包频率等参数，从源头减少客户端需要渲染和处理的实体与数据量。
实体追踪范围缩减
Client FPS
将实体追踪范围乘以 0.75（可配置），减少客户端需要渲染的实体数量。追踪范围越小 = 客户端渲染的实体越少 = FPS 越高。
multiplier: 0.75 -25% entities
远端实体更新包降频
Client FPS
距离玩家超过 32 格的实体，位置更新包发送频率从每 tick 降到每 5 tick，减少网络流量和客户端插值计算。
interval: 5 ticks threshold: 32 blocks
动态视距管理
Client FPS
根据在线玩家数量和服务器 TPS 动态调整视距。玩家多时自动缩小视距（最低 4），减少客户端加载的区块和实体数量。
min: 4 / max: 16
区块数据包优先级排序
Client FPS
按玩家位置为中心螺旋排序区块发送顺序，确保玩家附近的区块优先加载，减少等待时间。
spiral order
实体元数据批量打包
Client FPS
将多个实体元数据更新包合并为单个包发送，减少数据包数量和客户端处理开销。
batch per tick
自适应实体追踪
Client FPS
当服务器 TPS 低于 15 时，自动进一步缩减实体追踪范围，在低性能环境下保护客户端 FPS。
TPS < 15 → shrink
